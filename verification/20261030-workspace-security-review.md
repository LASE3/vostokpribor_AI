## Findings reported to root and repairs

1. High: Fail-closed audit introduced an authentication ordering risk. The former Auth::attempt granted a session before the controller logged LOGIN_SUCCESS, so an audit insertion exception could return500 while keeping authentication. Root centralized last-login/audit writes in a transaction before granting a new session and removed duplicate controller/HTML success audits.
2. Medium: RangeClient could return success=true for HTTP500 if the body happened to contain success=true. Root now normalizes every non-OK HTTP result to failure and normalizes invalid/cross-origin URLs.
3. Medium: ADMIN could create student-authored notebook/model/experiment work with no ticket through shared creation services. WorkOwnership::student now requires an active STUDENT for student creation/save/upload/run/request operations. SOC reads still inspect original owners and original notebook code; administrative annotations are separate fields.
4. Medium: Same-student but different-ticket notebook/run/model references were accepted. Experiment and model services now verify related records belong to the same ticket.
5. Medium: Existing deployment code blocked all record creation and decisions, preventing an administrative workflow. It now records PENDING requests and APPROVED/REJECTED decisions independently from runtime deployment, with provider NOT_CONFIGURED, null endpoint, no verified quality score, actual actor audit, and idempotent retries. It rejects fabricated DEPLOYED.
6. Low: New notification links had a fixed root path. New workspace/deployment notifications now use AppUrl::to for the nested XAMPP mount.
7. Reported to root: Audit failure during logout should never prevent clearing the PHP session; use a finally boundary. Audit resource identifiers from full request URIs also need deliberate schema-length bounding for strict MySQL mode. Root owns these core repairs and final validation.

## Trust and boundary notes

- The central SOC route guard runs before controller business handlers; each service additionally verifies an active administrator rather than trusting body roles.
- Repository filters use allowlisted resources/columns and prepared values; pagination is bounded and validated. Student IDs resolve actual STUDENT rows.
- Notebook/experiment/model/student IDs never transfer ownership when reassignment occurs. Revoked ticket grants no longer authorize new student work.
- Admin model update permits only admin_label/admin_notes/archive or restore; it cannot replace student name, student experimental metrics, artifact bytes or notebook cells.
- Stored deployment requests/approvals are not provider results. Inference remains NOT CONFIGURED; no endpoint is generated or linked.
- Worker and host bridge remain disabled. Trusted model quality/deserialization/benchmarking remain unavailable, independent of file integrity.
- New admin pages use the existing AppLayout and vp components. No shared layout/CSS/logo source was altered by this scope.

## Remaining infrastructure limitations

BLOCKED: isolated execution runner, trusted quality evaluator, verified inference provider and real cancellation-to-runtime termination guarantees. Database queue cancellation is clearly labeled separately from runtime termination.
