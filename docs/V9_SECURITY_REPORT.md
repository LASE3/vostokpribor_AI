# V9 security assessment

Assessment date: 2026-11-01. Scope is the existing PHP/PDO application on `main`, its release source and the inspected local XAMPP host. This report distinguishes baseline proof, current repairs and deployment blockers. It is not a penetration-test certification or approval to expose XAMPP publicly. Exact final regression, browser, staging, recovery and dependency results are maintained in `V9_TEST_RESULTS.md` and `V9_FINAL_REPORT.md` by the release verification pass; absence of a result is not a pass.

## Confirmed source-auditor defects and repair

The original auditor executed during import, rewrote historical reports and classified dependency, development and verification code as live application. Its baseline reported 64 operational blockers across 1,114 files. That total was not evidence of 64 exploitable application defects. The new version makes scope explicit, retains every contextual finding, includes `.cjs`/`.mjs`, protects source/report paths and reports operational review requirements separately. It scans private source strictly as text without running it or deleting anything.

The exact migration metadata backfill and two known UI-only cases have narrow explanations. Unknown operational patterns, unexpected migration inserts and active-source unreadable/link coverage continue to require review. The complete occurrence list is in `verification/v9-20261101/source-audit-current.json`; inventory hashes are in `source-inventory-current.json`. Because other V9 changes can add files, use the final rerun's counts rather than a frozen interim number.

`python tests/source_audit_v9.py`: **15 passed**, no skipped symlink tests on the observed Windows account. `python tests/infrastructure_preflight_v9.py`: **6 passed**. Logs are `source-auditor-tests.log` and `infrastructure-preflight-tests.log`. These tests verify the tools' boundaries and truthful disabled reporting; they do not create or mutate a database.

## Infrastructure findings and deployment blockers

The inspected host lacks Docker/Podman/Kubernetes tooling and installed Docker/WSL/Hyper-V services. WSL status explicitly reports not installed; relevant optional features are disabled. No independently authenticated runner/evaluator/inference adapter, enforced resource/network policy or adversarial service acceptance evidence exists. Exact read-only inventory is in `isolation-inventory.json`; WSL/service command exits are in `isolation-platform-baseline.json`.

Execution remains disabled after authorization. Validation proves uploaded-file integrity only and reports `NOT_EVALUATED` for quality; student metrics are not trusted evidence. Deployment approval remains a database decision with no live endpoint. The trusted disabled worker returned **78** and emitted only its unavailable message (`disabled-worker.log`). The new read-only preflight also returned **78**, regardless of detected tool presence (`infrastructure-preflight.json`).

No Docker socket, permissive subprocess runner, environment flag bypass, fabricated quality score or fake inference provider was introduced. A future implementation must pass the independent identity, filesystem/network/resource, cancellation/cleanup and provenance gates in [the architecture assessment](V9_ARCHITECTURE.md). Docker's daemon and rootless guidance and gVisor's architecture show why detecting a binary cannot establish this boundary: [Docker security](https://docs.docker.com/engine/security/), [rootless mode](https://docs.docker.com/engine/security/rootless/), [gVisor architecture](https://gvisor.dev/docs/architecture_guide/intro/).

The complete AI engineering range and public production deployment therefore remain blocked until the required infrastructure and release gates have real evidence. This does not prevent testing and using the persisted non-execution training workflow on localhost.

## Final verification supplement — 2026-11-01

Final results supersede baseline counts: 49 security-unit, 89 policy, 98 actual request-security and 104 adversarial SOC assertions passed. All 183 registered API routes reached application authentication/CSRF handling on Apache rather than a missing rewrite. Cross-student ticket/dataset/notebook/model/submission reads and referenced-object writes were rejected. The 257-check workflow independently checked 30 SQL persistence results. Disabled execution returned503; manual perfect metrics remained USER_REPORTED and quality NOT_EVALUATED; approved requests exposed no runtime endpoint. See V9_TEST_RESULTS.md for every suite and limitation.

Older HTTP suites now check the saved testing database, exact loopback URL and actual separate cookie before credentials. Twenty-four actual wrong-URL/wrong-cookie runs refused before writes. File-writing PHP suites additionally require a matching saved testing .env and an explicitly prepared tree/database marker. Ten guard assertions and positive reruns passed. An earlier env-only test-storage gap briefly retained one test-owned model file in main's storage; its exact checksum, test owner and zero main references were verified before moving it to the matching isolated test tree. All 52 original private files and every original non-migration database row still match the encrypted backup. This correction is documented rather than omitted.

The six-category recursive source audit covered1,160 files with zero coverage/encoding gaps or blocking findings. All190 contextual occurrences remain in the evidence; three active matches are benign identifiers/copy/comments. Offline Git inspection covered1,029 reachable blob/commit objects across20 commits, with zero tracked .env paths or matching well-known key formats; eight historical bcrypt fixture hashes remain. Git history was not rewritten and is excluded from release. npm audit reported zero known vulnerabilities in the pinned installed build dependency tree. Neither scan constitutes a penetration-test certificate.

Restricted DML-only staging identities were verified through actual grants, DDL/source-database denials and HTTP work. The existing main operator configuration was preserved and is not public-ready. PHP8.2 branch security support does not make the installed8.2.12 patch current; Apache2.4.58 is old and MariaDB10.4 maintenance ended2024-06-18. No runtime upgrade, public HTTPS, external monitoring or production acceptance was performed. Vendor references: [PHP support](https://www.php.net/supported-versions.php), [Apache advisories](https://httpd.apache.org/security/vulnerabilities_24.html), [MariaDB maintenance](https://mariadb.org/about/#maintenance-policy).
